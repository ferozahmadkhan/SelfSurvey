The Problem

Why Google Forms
isn't enough for research

When conducting a psychology study, Google Forms created 5 critical blockers that compromised research integrity.

🔓

Weak Duplicate Prevention

The "Limit to 1 response" feature only requires a Google login. Anyone with multiple accounts can submit multiple times — invalidating research data.

🏢

No Data Ownership

All responses are stored on Google's servers. For academic research, data privacy cannot be guaranteed and Google's terms apply to everything.

📋

Limited Question Types

No proper Likert scales, no matrix questions, no response timing to detect rushed submissions, and no attention check mechanisms.

📊

No SPSS Export

Psychology research requires SPSS for statistical analysis. Google Forms only exports to Google Sheets or CSV — never directly to SPSS.

🚫

Response Limits

Free Google Forms accounts have monthly caps that can derail large-scale research studies requiring 100+ responses.

🔑

Requires Google Account

Enforcing the 1-response limit requires participants to have and use a Google account, excluding a significant portion of potential respondents.

Troubleshooting

8 issues encountered.
8 issues solved.

Every problem documented with root cause analysis and the exact fix applied — a reference for future builders.

ISSUE 01 File Manager Upload Stuck at 1%

InfinityFree's File Manager froze at 1% and could not handle the 107MB ZIP file upload.

InfinityFree's web-based File Manager has a strict file size upload limit.

Switched to FTP upload via FileZilla which bypasses web upload limitations entirely.

Always use FTP for large file uploads to shared hosting environments.

ISSUE 02 FileZilla Blocked by Windows Smart App Control

Windows blocked the FileZilla installer: "Smart App Control has blocked this app".

The default download is a "sponsored2" version with bundled software that triggers Windows security.

Downloaded the clean version without bundled offers from FileZilla's additional download options page.

Always download the plain/clean installer version of FileZilla — not the default sponsored one.

ISSUE 03 FTP Transfer Failures — IPv6 Error 522

FileZilla transfers kept failing with "Response: 522 Only IPv4 is supported".

Windows resolved ftpupload.net to IPv6 (64:ff9b::b91b:860b) but InfinityFree only accepts IPv4.

Disabled IPv6 in Windows Network Adapter settings. Used IP 185.27.134.11 directly in FileZilla.

When using FTP with InfinityFree, always use the IPv4 address directly to avoid resolution issues.

ISSUE 04 InfinityFree Has No SSH/SFTP

Attempted to use SFTP for more reliable file transfer but InfinityFree does not support it.

Free shared hosting providers don't provide SSH access for security and resource reasons.

Stayed with FTP after fixing the IPv6 issue — worked reliably once the IP was used directly.

Free hosting providers rarely offer SSH/SFTP. Always plan for FTP-only environments.

ISSUE 05 000webhost Redirected to Hostinger (Paid)

Tried 000webhost as an alternative free host but it redirected to Hostinger's paid platform.

000webhost was permanently shut down by Hostinger and merged into their paid service.

Stayed with InfinityFree after successfully fixing the IPv6 FTP issue.

Always verify that free hosting services are still operational before investing setup time.

ISSUE 06 Email Sending Failed

LimeSurvey could not send invitation emails. Error: "Could not instantiate mail function".

InfinityFree's free hosting blocks PHP's built-in mail() function entirely.

Switched to manual link sharing — copied each participant's unique token URL and shared via WhatsApp.

Free hosts block outgoing email. Always have a manual link-sharing fallback ready.

ISSUE 07 Survey Showed "Expired" After Settings Change

After changing participant settings, the survey showed "expired and no longer available" to respondents.

LimeSurvey automatically deactivates a survey when major settings are changed — a data safety feature.

Simply reactivated the survey from the admin panel — all data and settings preserved.

After changing major settings in LimeSurvey, always remember to reactivate the survey.

ISSUE 08 Anonymized Responses Cannot Be Changed After Activation

After activating with "Anonymized responses: On", could not turn it off to identify respondents.

LimeSurvey permanently locks the anonymization setting after first activation to protect respondent privacy.

Added explicit name and email questions inside the survey — respondents voluntarily identify themselves.

Always configure anonymization settings BEFORE activating a LimeSurvey survey for the first time.

How It Works

Bulletproof duplicate
prevention explained

A multi-layer approach using token-based access combined with cookie persistence for both closed and open surveys.

Token Flow — Step by Step

1
Researcher adds participant Name + email added to participant list
2
System generates unique token TzsZC47kngsdD3N
3
Participant receives unique link /index.php/458434?token=TzsZC47...
4
Participant fills and submits survey All responses recorded to database
5
Token marked as USED Permanently locked in the database
✗
Any future attempt → BLOCKED Same token, any device, any browser — denied
